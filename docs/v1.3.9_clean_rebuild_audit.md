# v1.3.9 클린 재작업 감사 기록

## 기준과 공개 상태

- 기준 커밋은 공개 `v1.3.8`의 `17c0230a`이다.
- 클린 재작업 결과는 `main`의 v1.3.9 커밋과 공개 v1.3.9 Release로 배포되었다.
- 철회한 v1.3.9의 변경을 그대로 신뢰하지 않고, 각 제보의 실제 ROM 주소와
  Xvfb 화면을 다시 확인한다.

## 철회한 구현에서 확인된 원인

### 상점 아이템 이름과 UI 그래픽

v1.3.8은 긴 아이템 이름의 뒤쪽 글꼴을 `0xA700..0xB3FF`에 두지만 상점
설명 DMA 뒤에 다시 적재하지 않아 `크라운`, `천사날개`, `그레이프니르` 등이
깨졌다. 철회한 v1.3.9는 이를 고치려고 `0xB400`, `0xB700`, `0xB800` 영역을
새 글꼴 뱅크로 사용했다. 그러나 그 세 영역은 상점 아이콘·페이지·오른쪽 상태
패널이 실제로 사용하는 VRAM이라 `단검` 옆 문양과 AT/DF 앞의 `니`가 생겼다.

새 구현은 v1.3.8의 안전한 `0xA700..0xB3FF`만 유지하고, 상점 설명 DMA가
끝나는 ROM `0x0272D2`에서 이름 글꼴을 다시 적재한다. B400/B700/B800은
전혀 쓰지 않는다. 세부 주소와 실패 화면은
[상점 VRAM 재작업 기록](v1.3.9_shop_vram_rework.md)에 보존한다.

### 전장 `명령`의 `자동`

철회한 v1.3.9는 `0x0A2BAC`의 `자`를 `수`로 바꿨다. 이 주소는 전장 명령이
아니라 지휘관 배치의 `자동배치` 글꼴 목록이다. 그래서 실제 하위 메뉴는 계속
`자동`이었고, 별도 자동 배치만 잘못 바뀔 수 있었다.

실제 하위 메뉴는 `0x09706A`의 공용 글꼴 목록과 `0x09768C`의 네 행 토큰을
쓴다. 마지막 행이 24번 슬롯과 1번 `동`을 조합하므로 24번만 `수`로 바꿨다.
`0x0A2BAC`은 v1.3.8의 `자`로 복원했다.

## 시나리오 15 대사 대응 감사

문제는 영문판의 논리 대사 번호를 일본판의 물리 페이지에 한 칸씩 그대로
대응한 데서 생겼다. 일본판 이벤트 코드의 실제 포인터를 기준으로 다음 물리
페이지를 다시 대응했다.

| 일본판 물리 페이지 | 올바른 의미 |
| --- | --- |
| `0x1A00AA` | 어서 임무로 돌아가! |
| `0x1A00C6` | 우와… 정말 지독한 여자군… |
| `0x1A00E8` | 저 여자는 부하를 아끼는 마음도 없나? |
| `0x1A012A` | 이멜다에게 한 발자국도 못 간다! |
| `0x1A0182` | 이렇게 된 이상 돌격이다! |
| `0x1A01A0` | 으윽… 이멜다님…! |
| `0x1A01C0` | 이 정도 상처쯤 괜찮아! |

정적 검사는 위 주소, 일본판 소스 참조, 이벤트 포인터와 한국어 문장을 함께
잠근다. 이어서 이벤트 코드는 그대로 둔 채 고정 레코드 1번 지휘관만 엘윈
아래 `(3,3)`으로 옮기고 AT/DF와 용병만 제한한 비배포 진단 ROM을 만들었다.
일반 공격으로 실제 HP를 0으로 만든 뒤 다음 적 페이즈 전체를 실행했다.

| 실기 확인 지점 | 결과 | 캡처 SHA-256 |

| 격파 직후 지휘관 | `이멜다님, 도와주세요… 이멜다님!` | `d5476e6c969b1eb19c9e8d3ef37d21a8f15d6b74112c2df03b70709e70521cf0` |

중간의 퇴각 요청·증원 요청·이멜다의 위협·임무 복귀 명령과 헤인·레스터
반응도 총 18개 대사 화면으로 순서대로 확인했다. 대상 지휘관은 최종 저장
상태에서 격파 플래그 `0x80`, HP 0이었고, 행동을 시작한 다른 지휘관에게
사망 대사가 붙는 현상은 재현되지 않았다.

## v1.3.8 대비 변경 경계

생산 ROM을 바이트 단위로 비교하면 Original과 Normal은 각각 881바이트,
Hard는 883바이트가 v1.3.8과 다르다. 차이는 버전·체크섬, 상점 이름 로더와
재배치 코드, 전장 `수동` 글꼴, 마법 MISS 글꼴 충돌 해소, 시나리오 1 서장,
시나리오 15 대사 페이지, 레스터 자베러 전직 체인에 해당하는 주소 페이지만
사용한다. 시나리오 배치표(`0x18xxxx`), 클래스 경험치 곡선, 하드 밸런스
테이블에는 새 차이가 없다.

따라서 철회본의 상점 B400/B700/B800 덮어쓰기와 잘못 겨냥한 자동배치 글꼴은
현재 델타에서 제외됐고, v1.3.8의 게임 진행·밸런스 데이터는 그대로 유지된다.
