# v1.3.9 상점 VRAM 재작업 기록

이 문서는 v1.3.8에서 v1.3.9로 옮기는 과정에서 확인된 상점 아이템 이름과
UI 그래픽 충돌을 기록한다. 공개 v1.3.9는 내려간 상태이며, 아래 작업은
`v1.3.9-clean` 비배포 브랜치에서 v1.3.8을 기준으로 다시 진행한다.

## 재현한 두 문제

### v1.3.8의 긴 아이템 이름

v1.3.8 Normal에서 원본의 전체 아이템 상점 목록을 여는 진단 ROM을 만들고
ID 31~37을 실제로 이동했다. 첫 상점 화면의 `단검`과 오른쪽 AT/DF 수치는
정상이지만, 준비 화면이 먼저 사용한 `0xA700..0xB3FF`를 상점 진입 때 다시
읽지 않아 뒤쪽 이름 글꼴이 다른 그래픽으로 남았다.

- `크라운`의 마지막 `운`이 다른 글자로 보였다.
- `천사날개`, `카벙클`, `그레이프니르`도 뒤쪽 글자가 다른 UI 그래픽으로
  보였다.
- 재현 캡처 SHA-256은 ID 31
  `1cc767a472d2d36bf09a83e23980b14d7e9c490fd87074a33d6640be0d5d6ad3`,
  ID 33 `85cc86e5cc9356117103cf56a0bcf076eb49dda4547488da7b3a1b83cdb94cb2`,
  ID 35 `90d91dc13f55bcc9fe4b1afe0de9d79652e7a49ed3003007d1cca20be433daff`이다.

### 철회한 v1.3.9의 상점 UI 손상

첫 v1.3.9 구현은 긴 이름 22자를 `0xB800..0xBFFF`,
`0xB400..0xB5FF`, `0xB700..0xB7FF`에 나눠 올렸다. 그러나 이 영역은
빈 공간이 아니다.

- v1.3.8 시나리오 1 상점의 실제 Plane/SAT 분석에서 `0xB800` 영역의
  타일 `0x5F8`, `0x5F9`, `0x5FC..0x5FF`가 화면에서 사용 중이었다.
- 해당 영역에 한글을 올린 v1.3.9 화면에서는 `단검` 옆 아이콘이 변하고,
  오른쪽 캐릭터 AT/DF 수치 앞에 `니`가 나타났다.
- 문제 화면 SHA-256은
  `ec2c7f9051d3f51e27799be5e71437c32c54274f72af6a6b30f62272d90a6dc9`이다.
- B400/B700/B800을 상점 진입 때 백업하고 준비 화면 복귀 때 복원하는
  후속 시도는 상점에서 나온 뒤만 고쳤다. 상점 안에서는 계속 손상된
  타일을 표시하므로 근본 해결이 아니었다.

## 새 구현 원칙

1. v1.3.8의 `0xA700..0xB3FF` 이름 영역을 유지한다.
2. 상점 설명 글꼴 DMA가 `0x5400..0xA6FF`를 채운 직후인 `0x0272D2`에서
   아이템 이름 글꼴을 다시 읽는다.
3. 상점과 전장에서 사용 중인 B400/B700/B800은 전혀 쓰지 않는다.
4. 기존 장비 화면 전용 `0x5400` 재로딩 경로는 그대로 유지한다.
5. 검증은 단검 화면의 아이콘·오른쪽 AT/DF 패널과 ID 31~37의 실제 이름을
   모두 포함해야 하며, 상점 복귀 화면만 비교해서 통과시키지 않는다.

## 검증 상태

- v1.3.8 기준 시나리오 1 준비·상점·복귀 14쌍 캡처 완료.
- 새 상점 진입 재로딩 구현 완료. Normal 후보의 MD 체크섬은 `2E0A`,
  SHA-256은
  `36a857eeef644032eedcdaa2168e81ac1fa39c1dd429f6ec38dcd51aa7b50c71`이다.
- 전체 아이템 1~37을 가상 화면에서 실제로 이동하며 모두 캡처했다. 단검 화면의
  오른쪽 캐릭터/AT/DF 영역과 아래 단검 설명 영역은 v1.3.8 정상 기준과
  픽셀 단위로 같았다.
- ID 31 `크라운`, ID 33 `천사날개`, ID 35 `그레이프니르`, ID 36
  `걀라르호른`을 포함한 마지막 일곱 이름이 모두 정상으로 보였다. 대표 캡처
  SHA-256은 각각
  `0040e053298fc804199699b7f47753172502a2525e6226813fd573c7a994d818`,
  `e242b6ead42b72ed4a9fd6e90e07332420fe5c268970f9d53376780d19efbec5`,
  `2c7a24024a68212f0e03229c265a67336a60968aa7212babadb4b44d973a14a3`,
  `fd905921bb037774ce328de5bf8acae75b494b0eb04ffc5492145642e52b8013`이다.
- 단검을 실제로 구입·판매한 팝업과 준비 화면 복귀를 확인했다. 단검 옆 문양,
  AT/DF 앞 `니`, 커서 잔상은 재현되지 않았다. 준비 화면 상점 진입 전후
  14개 대응 화면도 모두 픽셀 단위로 같았다.
- 시나리오 15의 제보 격파 분기를 포함한 나머지 v1.3.9 변경 회귀 검증은
  별도 검증 기록에서 계속 관리한다.

## 명령 하위 메뉴 검증 오류와 수정

철회한 v1.3.9는 `자동`을 `수동`으로 고쳤다고 기록했지만, 실제 새 게임에서
지휘관의 `명령`을 열어 보니 여전히 `이동 / 공격 / 방어 / 자동`이었다. 당시
수정한 `0x0A2BAC`는 전장 명령이 아니라 지휘관 배치의 별도 자동 배치 메뉴였다.
그 결과 실제 문제는 그대로이고, 올바르던 자동 배치 글자만 `수`로 바뀔 수 있었다.

- 전장 `명령` 하위 메뉴는 `0x09706A`의 공용 글꼴 목록과
  `0x09768C`의 네 행 토큰을 사용한다.
- 마지막 행은 목록 24번과 `동`이 든 1번을 조합하므로 24번을 `수`로 바꿔
  `수동`을 표시한다.
- 지휘관 배치 목록 `0x0A2BAC`는 v1.3.8의 `자`로 복원해 실제 자동 배치를
  `자동`으로 유지한다.
- 수정 전 실기 화면 SHA-256은
  `41b1c012933ba914d30c2d5ebac9f054b24efc080ebffe918a66837650ba42de`이다.
- 수정 후 같은 Xvfb 새 게임 경로에서 하위 메뉴를 다시 열어
  `이동 / 공격 / 방어 / 수동`을 확인했다. 수정 후 캡처 SHA-256은
  `0887815c6f6a5a699767a8f0f77fdc5da660710080d9fc268e5f26a5c511ace9`이다.
- 같은 후보에서 지휘관 배치 화면도 열어 별도 항목이 `자동배치`로 정상 유지됨을
  확인했다. 캡처 SHA-256은
  `d1acb48522eb3ff36407382464d816ea99b46f9984a54d8dc60fa0f703e2ebb5`이다.
